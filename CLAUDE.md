# CLAUDE.md — Jogo de Torcidas

## Project Overview

**Jogo de Torcidas** is a Unity game that simulates Brazilian football (soccer) championships. It manages four national league divisions (Série A, B, C, D) and the Copa do Brasil knockout tournament simultaneously, advancing through rounds, applying promotions/relegations, and tracking multi-year historical records.

The project consists of exactly two C# MonoBehaviour scripts and a README. There are no build tools, package managers, CI/CD pipelines, or test files. All logic runs inside Unity at play time.

## Key Classes and Data Models

### `StatsCompeticao` (Serializable)
Holds per-competition statistics for a single team.

```csharp
public int pontos, vitorias, empates, derrotas, golsPro, golsContra, saldoGols;
public int grupoD; // active group number for Série D (1, 2, or 3); 0 = not used
```

### `TimeSerieA` (Serializable)
Represents any team across all divisions. Name reuse is historical; the class is used for teams in all four divisions and the Copa.

| Field | Description |
|---|---|
| `nome` | Team name string |
| `forca` | Team strength (1–100 scale, varies by division) |
| `cores` | Array of `Color` values used to render the team flag strip |
| `statsCompeticoes` | `Dictionary<string, StatsCompeticao>` keyed by competition name |
| `grupoD` | **DEPRECATED** — use `GetStats("BrasileiraoD").grupoD` instead |
| `pontos`, `vitorias`, … | **DEPRECATED** legacy fields kept for backward compatibility |

Competition name keys used in `statsCompeticoes`:
- `"BrasileiraoA"` — Série A
- `"BrasileiraoB"` — Série B
- `"BrasileiraoC"` — Série C
- `"BrasileiraoD"` — Série D
- `"Copa"` — Copa do Brasil

Always use `time.GetStats("BrasileiraoA").pontos`, not `time.pontos` (deprecated).

### `PartidaSerieA` (Serializable)
Represents a scheduled or played match.

| Field | Description |
|---|---|
| `rodada` | Round number (1-based) |
| `data` | `DateTime` of the match |
| `mandante` / `visitante` | Home/away team references |
| `golsMandante` / `golsVisitante` | Score (0 until played) |
| `foiJogada` | Whether the match has been simulated |
| `faseCopa` | Copa phase name (empty for league matches) |
| `foiParaPenaltis` | Whether a penalty shootout occurred |
| `penaltisMandante` / `penaltisVisitante` | Penalty score if applicable |

### `HistoricoDados` (Serializable)
Championship historical record: `ano` (year string), `campeao` (winner name), `vice` (runner-up name).

## Architecture

### Manager/UI Split

- `BrasileiraoManager` owns all game state and simulation logic. It is the single source of truth.
- `BrasileiraoUI` reads from the manager and renders into Unity UI prefab instances. It never modifies game state directly (except triggering `SimularRodadaOuIniciarAno()`).
- Communication is one-way: Manager → UI via `uiManager.AtualizarInterface(rodada)`.

### Round System

`TOTAL_RODADAS = 42` is the ceiling constant across all competitions:
- Série A/B/C: 38 rounds (19 turno + 19 returno)
- Copa do Brasil: rounds 3, 7, 11, 15–16, 20–21, 25–26, 30 (phase transitions)
- Série D: 30 rounds (group phase) + 11 rounds (final phase, rodadas 31–41)

`SimularRodadaOuIniciarAno()` is the main simulation driver called by the UI button each frame-cycle.

## Competition Details

### Série A / B / C
- 20 teams each
- 38-round double round-robin schedule (turno + returno)
- Top 4 earn promotion; bottom 4 are relegated
- Schedule generated by `GerarCalendarioPadrao(times, partidas, divisionType)`

### Série D
- 48 teams split into 3 groups of 16
- Groups assigned randomly each season by `DistribuirGruposSerieD()`
- 30 rounds of intra-group play (15 turno + 15 returno)
- After round 30, top 4 from each group (12 teams total) advance to a round-robin final phase (rounds 31–41, generated by `GerarCalendarioD_FaseFinal()`)
- Top 4 of the final phase earn promotion to Série C
- `faseFinalD_Iniciada` flag tracks whether the final phase has been generated

### Copa do Brasil
- 88 teams in the first phase: all of Série B (20) + C (20) + D (48)
- Série A's 20 teams enter directly in the second phase
- Phase structure with round triggers:

| Phase | Round triggered | Format |
|---|---|---|
| Primeira Fase | Round 3 | Single match |
| Segunda Fase | Round 7 | Single match |
| Terceira Fase | Round 11 | Single match |
| Oitavas de Final | Rounds 15–16 | Home + Away |
| Quartas de Final | Rounds 20–21 | Home + Away |
| Semifinal | Rounds 25–26 | Home + Away |
| Final | Round 30 | Single match |

- Home team for single-leg matches is always the **weaker** team by `forca`
- Ties in legs without aggregate use `DisputarPenaltis()` (probability-weighted by `forca`)
- `timesCopaVivos` tracks surviving teams; `timesCopaEntramFase2` holds the 20 Série A clubs

## Match Simulation Algorithm

`SimularPlacarGenerico(jogo, fatorZebra, fatorCasa, nomeCompeticao)`:

1. **Home advantage bonus**: +3 force for Série A home teams, +1 for others; away penalty mirrors this.
2. **Strength differential bonus**: applied to the stronger side based on `|forcaCasa - forcaFora|` ranges (1–5 → +1, 6–10 → +3, 11–15 → ±4, 16–20 → ±6, 21+ → ±10).
3. **Force clamped** to `[1, 100]`.
4. **Draw chance** = `max(1, round(mandante.forca * 0.3 + visitante.forca * 0.3))`.
5. **Result** drawn from weighted random: casa / fora / empate.
6. **Score** generated from fixed probability tables: `GerarPlacarVitoria()` and `GerarPlacarEmpate()`.
7. Stats updated on the per-competition `StatsCompeticao` object.

**Note**: the `fatorZebra` and `fatorCasa` parameters in `SimularPlacarGenerico` are no longer used; logic is division-inferred. They are kept for call-site compatibility.

## Team Strength (forca) System

Teams have a base strength that evolves each season via `AplicarEvolucao*` methods.

| Division | `forca` range | Promotion bonus |
|---|---|---|
| Série A | 15–100 | +5 ±5 (top 4), +2 ±5 (mid), -6→+3 (bottom) |
| Série B | 10–90 | +3 ±2→+6 (top 4), -4→+3 (rest) |
| Série C | 8–80 | graduated 4-tier system |
| Série D | 5–70 | graduated 3-tier system |

Initial strengths (season 2026): Série A tops are Palmeiras (50), Flamengo (48); Série D bottoms start at 4–7.

## Year Transition (`ProcessarViradaDeAno`)

Triggered when `temporadaFinalizada == true` and the simulate button is pressed.

1. Each division sorted by `StatsCompeticao` (pontos → vitorias → saldoGols).
2. Série D sorted using only the 12 teams in the final phase (from rodadas ≥ 31).
3. Champions logged to `galeria*` lists for each competition.
4. Strength evolution applied.
5. Bottom 4 of A relegated to B; top 4 of B promoted to A. Same pattern B↔C and C↔D.
6. `grupoD` reset and `DistribuirGruposSerieD()` called for the new season.
7. `IniciarTemporada()` called — increments `anoAtual`, generates fresh schedules.

## UI Architecture

### Panels
- `panelJogar` — main gameplay view (standings table + results)
- `panelGaleria` — historical champions gallery + all-time title ranking

### Division Selection
`divisaoAtualIdx` drives all data selectors:
- 0 = Série A, 1 = Série B, 2 = Série C, 3 = Série D, 4 = Copa do Brasil

### Standings Table (`MontarTabela`)
- Instantiates `prefabLinhaTabela` per team into `containerTabela`
- Each prefab row has 9 `TextMeshProUGUI` children: position, name, pts, W, D, L, GF, GA, GD
- One `RawImage` child renders a team flag (1×N pixel `Texture2D` from `cores` array)
- Color coding: green = promotion zone (top 4), red = relegation zone (bottom 4)
- Copa mode shows "VIVO" instead of points; shows champion trophy when Copa ends

### Results Panel (`MontarResultados`)
- Leagues: filter by `rodada` number
- Copa: filter by `faseCopa` string using `indiceCopaVisualizado` index into `fasesCopa[]`
- Navigation buttons `<`/`>` step through rounds (leagues) or phases (Copa)

### Gallery (`MontarGaleriaCompleta`)
- Shows champions in reverse chronological order
- Builds all-time title count ranking from `HistoricoDados` lists

## Code Style Observations

- Heavy use of **one-liner methods** and **inline lambdas** for sorting and filtering (e.g., `AplicarEvolucaoSerieA`, `Ordenar`).
- Multiple statements on single lines are common in the original code; new code may be more readable with standard formatting.

- `[Header("...")]` attributes organize Inspector sections in Unity editor.
- `[System.Serializable]` on data classes makes them visible in the Unity Inspector.
- There is **no dependency injection** — `BrasileiraoUI` accesses `manager` as a direct public field set in the Unity Inspector.

## Common Pitfalls

- **Cross-competition stat contamination**: always pass the correct `nomeCompeticao` string to `SimularPlacarGenerico`. Passing the wrong key will silently update stats in the wrong competition dictionary.
- **Série D final phase detection**: use `faseFinalD_Iniciada` flag or check `jogo.rodada >= 31` — do not filter by `grupoD` in the final phase since groups are not assigned for it.
- **Copa team list**: `timesCopaVivos` shrinks as teams are eliminated. After Copa ends it contains exactly 1 team (the champion). `timesCopaEntramFase2` is the static list of the 20 Série A clubs.
- **Round numbering**: `rodadaAtual` is incremented **after** simulation. When `AtualizarInterface` is called, it receives `rodadaAtual - 1` (the round that was just played).
- **Penalty results in Copa knockout**: single-leg ties use `DisputarPenaltis(TimeSerieA, TimeSerieA)` which returns the winner but does **not** save a score to a match object. The Copa Final uses `DisputarPenaltis(PartidaSerieA)` which saves to `foiParaPenaltis`, `penaltisMandante`, `penaltisVisitante`.
- **Schedule generation**: `GerarCalendarioPadrao` uses a round-robin rotation algorithm — the first team in the list is kept fixed and the rest rotate. Do not reorder the input list before calling it.

## Unity Setup Requirements

This project requires a Unity scene with:
- A GameObject with `BrasileiraoManager` component
- A GameObject with `BrasileiraoUI` component, with the `manager` reference wired in Inspector
- UI prefabs: `prefabLinhaTabela` (9 TMP texts + 1 RawImage), `prefabLinhaJogo` (4 TMP texts), `prefabLinhaHistorico`, `prefabLinhaRanking`
- TMP_Dropdown for division selection, Buttons for simulate/navigate/group selection
- ScrollView containers for table, results, history, and ranking

No external packages beyond TextMeshPro (bundled with Unity) are required.
